# Cross-window tutorial

The tutorial is optional and non-modal. It never opens/closes a workspace, creates a source, applies a Settings draft, or downloads a model. Home offers it only after its startup config, editor tabs, and conversations finish restoring. The current workspace remains usable; Home targets have titlebar alternatives when the empty Home screen is not visible.

## Ownership and progress

`@shared/types/tutorial` is the durable phase/step registry. The config file holds the progress revision; each Electron main process arbitrates a transient, exclusive BrowserWindow lease. `tutorial-coordinator.ts` only transitions after a successful claim; every transition includes the observed revision. Config writes are serialized across processes, and tutorial-only writes preserve unrelated raw fields and encrypted credentials. A conflict is shown to the user rather than retried or silently advanced. Unknown schemas, cursors, and opaque phase records are preserved and shown as unsupported. Closing a window releases its lease, not its progress. A renderer reload may retain the same webContents lease: a reentrant claim recovers it, while another window's claim is harmlessly denied. Separate app processes can each show the tour; disk revision checks still reject stale writes. For packaged `file://` windows, `main.ts` retains `index.html` as the hash-navigation base so native reloads can actually reload the renderer.

Only the ID of a user-created source is retained in progress, never draft contents. On reopening Settings the overlay checks that ID against the source rows: a missing source warns that its unapplied draft may have been lost, and an explicit **Return to Add source** action safely rewinds that phase. A saved but unselected source is identified separately. The tour never recreates a source, assigns a model to it, or clicks Apply; the Featured step may select a model for metadata preview only.

Each renderer mounts the overlay from `AppShell`; route data in `main.ts` identifies Home, Dependencies, and Settings. Health and Updater do not participate. Home waits for restoration before claiming. On an explicit action the owner advances, releases to the next window's role, and opens that window using `ElectronService`. The requested window claims exclusively; Home can reopen a failed handoff or reclaim an orphan and offer to resume. There is no focus-main IPC: when Dependencies remains open, the user returns to the main window themselves. Snoozing the invitation is session-only; **Dismiss remaining tour** / **Don’t show this tour again** dismiss unresolved shipped phases, while **Skip this phase** skips only the current phase.

**Settings → General → Behavior → Show the guided tour** has no flag of its own: it is ticked while any shipped phase is unresolved, so it cannot disagree with the tour's dismiss actions. Like other Settings it takes effect on Apply. Off dismisses unresolved phases; on clears the resolutions this release understands so Home invites again. The `tutorial:set-enabled` IPC is the one tutorial write that needs no lease or expected revision, because it applies a saved preference to whatever progress is current; it then ends the current lease and any handoff.

Dependencies exposes `data-tutorial-llama-state`, `data-tutorial-llama-busy`, and `data-tutorial-dependencies-busy`. The coordinator closes that window only on an explicit advance from `engine-install`, after a validated `success` or trusted already-installed acknowledgement, and only while both busy flags are `false`. An error, cancel, unknown/checking status, skip, or any other active/cleaning-up dependency leaves it open. No progress event or component teardown alone is proof of a successful install.

## Adding a phase or target

1. Add stable IDs and order to the shared registry first. Never repurpose persisted IDs; keep migration/downgrade behavior for unknown IDs. Add exactly one presentation descriptor per registry step in `tutorial-steps.ts`, and update the registry-coverage spec.
2. Give each descriptor a window, accurate text, and ordered `data-tutorial` target names. Put attributes on meaningful, preferably interactive elements, not brittle CSS selectors. Give conditional/loading/filtered targets an actionable `unavailableHint`; never automatically skip or mutate app state when a target is absent. If a Home target disappears with a workspace open, provide an appropriate always-visible alternative.
3. Preserve the underlying control's normal behavior. The outline and mascot do not accept pointer events; only the card does. The overlay remeasures on nested scrolling, viewport resize, DOM/layout changes, and target resize. Hidden, clipped, offscreen, and absent elements must be handled; keep Retry, Continue, and Skip available. No focus trap, automatic scrolling, or automatic click is required.
4. On every rendered cursor the overlay emits `window`'s `clara-tutorial-step` CustomEvent with `{ phaseId, stepId }`. A late-mounted Featured Small row causes the preview event to be re-emitted. Consumers must be idempotent and narrowly scoped: the Model Manager may preview metadata only on `featured-preview`, must respect an intentional selection, and must not download a model.
5. For cross-window transitions, use the role of the **next persisted descriptor**, not a timeout or DOM event as proof of progress. Opening Settings for Featured uses `modelManager`; moving from Featured to Sources in the same Settings window asks the user to select Sources and leaves any draft intact. External documentation is a normal `target="_blank"` HTTPS link, handled by the existing hardened-window external-link handler.
6. Test registry coverage, exclusive ownership and stale revisions, window closure/recovery, conditional targets, keyboard/live announcements, scrolling/repositioning, reduced motion, and any side-effect-sensitive action. The mascot is decorative, honors reduced-motion settings, and celebrates only on the final step.

It uses a temporary config and offline fixtures: no real model or engine download occurs. Set `TUTORIAL_SMOKE_SCREENSHOT_DIR` to a directory to capture optional visual checkpoints.
