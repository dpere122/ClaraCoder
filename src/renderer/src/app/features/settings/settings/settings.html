Edit tools

Controls which file-edit tools the model can call when Editor mode is on in the chat toolbar. Standard includes search-and-replace snippets; strict keeps only line-range and full-file edits (fewer ambiguous matches).

When on, the main agent can call nested planning tools (plan_and_modify, execute_workspace_mutation). When off (default), use staging edits only—the app is moving toward a new default planning approach.

When Editor is on, Clara runs a LangGraph Learn → Write → Verify loop: read-only discovery, then mutations and nested work, then any pending staged → workspace transfers, then pytest/smoke plus LSP diagnostics (bounded retries if checks fail). Off by default.

When on, nested code review may run run_staging_overlay_command: a temporary copy of the workspace with staged drafts applied (argv-only subprocess; no shell). Off by default.

Read and search limits

Caps how much one tool call can return. Higher values use more context window; very large reads may feel slow on big files.

Default text encoding and newlines

Used when the model omits encoding / newline on read, search, and edit tools. Per-call overrides still apply. preserve matches existing file line endings when the file already exists; new files use LF.

Editor mode in the chat window still controls whether write tools are bound at all. This page only changes how those tools behave and how much read/search tools return per call.
